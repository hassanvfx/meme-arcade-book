# Evidence sheet

## Question

How can a Swift package make an iOS capability independently testable and consumable without creating a disguised app dependency?

## Public evidence

- `ios-framework` locked at `003d168e48b6079205585f117b2553ada80c52d0`.
- `Package.swift` declares a `FrameworkLib` library product, source target, and test target with explicit platform floors.
- `DemoApp` is a separate SwiftUI Xcode application importing `FrameworkLib`.
- Apple's public tandem/local-package documentation, linked from the repository README.

## Approved generalized MemeArcade evidence

- Product orchestration and specialized infrastructure are separate responsibilities.
- A reusable capability must make its dependency direction and lifetime legible before extraction.

No private target graph, package name, source excerpt, endpoint, payload, or build configuration is approved for publication.

## Claims requiring approval

- Any exact claim about MemeArcade's private package layout.
- Any performance, release, or dependency metric from the production app.

## Planned diagram

Demo app → library product → library target, with tests attached to the capability and no reverse dependency from the package to the app.
