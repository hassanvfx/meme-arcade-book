# Evidence sheet

## Question

How should a native iOS root retain ownership of product state while specialized remote runtimes participate in a hybrid application?

## Public evidence

- Hassan Uriostegui, “Building Reactive Applications with SwiftUI and Combine” — public article used for reactive state and view-update concepts.
- GamePlayer locked source — public evidence that a native UIKit pager can host isolated web gameplay without giving the browser product-navigation ownership.

## Approved generalized MemeArcade evidence

- A SwiftUI root coordinates application state and routes into a separate UIKit/WebKit pager responsibility.
- Feed/catalog responsibilities are separate from root product orchestration.

No private source excerpts, type names, routes, endpoints, payloads, or diagrams are approved for publication.

## Claims requiring approval

- Any claim beyond the two generalized responsibility statements.
- Any private implementation example or production metric.

## Planned diagram

Intent → native product state → feature boundary → isolated web runtime, with route and lifecycle policy remaining native-owned.
