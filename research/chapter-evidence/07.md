# Evidence sheet

## Question

How can an iOS host grant a remote interactive page the capability it needs while retaining native control of navigation, lifecycle, storage, and product actions?

## Public evidence

- GamePlayer locked at `2e9f314b8f775b2d9564950d1baeb2baa920421b`.
- `MAWebViewFactory` configures non-persistent website data, JavaScript, and inline/autoplay media.
- `MAWebNavigationPolicy` allows only HTTPS URLs with a host; public tests reject HTTP, file, data, JavaScript, custom, and invalid schemes.
- `MAStagePlayerCell` applies the policy to both navigation actions and responses, lazy-loads primary content, and exposes native action controls.
- The public README states there is no JavaScript bridge or native script injection and records the all-HTTPS-host versus curated-allowlist trade-off.

## Approved generalized MemeArcade evidence

- Native owns product navigation, lifecycle, device policy, and routing at the hybrid boundary.
- Remote content owns only its authorized interactive surface.

No private hostname, origin, configuration, bridge protocol, header, cookie, content, script, route, source, security finding, or metric is approved for publication.

## Claims requiring approval

- Any exact private WebView configuration or trust-policy claim.
- Any production security finding, remote-content behavior, or performance measurement.

## Planned diagram

Native policy/container → constrained WebView session → remote interactive surface, with native product actions and durable state excluded from the remote side.
