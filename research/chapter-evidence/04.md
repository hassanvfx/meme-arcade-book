# Evidence sheet

## Question

How can an iOS application restore safe device-bound state without treating stale local data as current product authority?

## Public evidence

- `ios-storage` locked at `8e1b791e36719f8079f26b6493fc41b9ff7c6360`.
- `DatastoreItem` declares a Codable item, key, publisher, default, and restore callback.
- `Datastore` is an actor; its public implementation restores then observes a throttled publisher.
- Its encrypted path uses CryptoKit AES-GCM and a symmetric key obtained through Keychain APIs.
- Restore errors fall back to the model default in the public implementation.

## Approved generalized MemeArcade evidence

- The app integrates application-state persistence at the device boundary.
- Private schemas, keys, record values, migration history, and storage implementation are not publication-approved.

## Claims requiring approval

- Any precise MemeArcade encryption, key-management, retention, or migration claim.
- Any private record, source excerpt, endpoint, account data, or game identifier.

## Planned diagram

Live model → safe Codable representation → durable store → validate/migrate/recover → native product state.
