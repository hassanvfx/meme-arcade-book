# Question

How can a native iOS feed host remote web gameplay without assigning paging, lifecycle, or trust decisions to the browser?

# Public evidence

- GamePlayer at locked revision `2e9f314`: README and project map document UIKit paging, reusable stage cells, lazy activation, ephemeral WebKit storage, HTTPS-only navigation, and no JavaScript bridge.

# Production evidence

Read-only sibling reconnaissance identifies a dedicated UIKit/WebKit vertical-pager module, SwiftUI root and application state, fullscreen session coordination, and separate feed/catalog services. No source excerpt, URL, catalog item, payload, or private implementation is approved for publication.

# Approved claims

- Native owns page movement and product orchestration; the remote game owns game interaction.
- Lazy activation and bounded reuse are preferable defaults to catalog-wide WebView creation.
- Prewarming requires measurement on target hardware.

# Diagram

Native root → feed provider → pager → primary stage cell → isolated WebView game, with product callbacks returning to the native root.
